# Алхимический котёл

Калькулятор алхимии: считает эффекты зелья, гасит взаимно противоположные
свойства и подгоняет омнисенцию кристаллами ихора и кенома.

Есть два интерфейса:

- `main.py` — консольный (читает Python-справочники, см. «База данных»);
- `app.py` + `web/` — веб-страница. Ноутбук работает как локальный хостинг,
  остальные устройства в той же сети открывают её по IP.

Ингредиенты живут в SQLite и редактируются через `/admin` — код править не нужно.

## Веб-версия

### Установка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

### Запуск

```bash
.venv/bin/python app.py
```

Скрипт напечатает два адреса:

```
На этом ноутбуке:  http://127.0.0.1:8000
В локальной сети:  http://192.168.x.x:8000
```

Второй адрес вводят телефоны и другие ноутбуки, подключённые к тому же роутеру.

Если avahi запущен, имя хоста обычно тоже работает: `http://<hostname>.local:8000`
(mDNS; не все телефоны это умеют — тогда только по IP).

Переменные окружения:

| Переменная               | По умолчанию     | Что делает                          |
| ------------------------ | ---------------- | ----------------------------------- |
| `ALCHEMY_PORT`           | `8000`           | порт сервера                        |
| `ALCHEMY_DEBUG`          | —                | `1` включает авто-перезагрузку Flask |
| `ALCHEMY_DB`             | `data/alchemy.db`| путь к файлу базы                   |
| `ALCHEMY_ADMIN_PASSWORD` | —                | включает пароль на `/admin`         |
| `ALCHEMY_ADMIN_USER`     | `admin`          | логин для `/admin`                  |

### Интерфейс

На ноутбуке — три колонки: ингредиенты слева, котёл в центре, инструкция справа.
Три колонки сохраняются и на планшете в горизонтали (от 1000 px), так что
кнопки «Сварить» / «Очистить» остаются на экране.

Уже 1000 px (телефон, планшет в портрете) включается мобильный режим:

- сверху вкладки «Ингредиенты / Котёл / Помощь» — открыта одна панель;
- снизу липкая панель: количество, сырая омнисенция и кнопки «Очистить» и
  «Сварить», поэтому обе доступны без прокрутки;
- на вкладке «Котёл» — тот же котёл, нажатие на него варит;
- результат выезжает шторкой снизу, кнопки шторки всегда видны (прокручивается
  только содержимое).

На низких экранах (меньше 620 px по высоте) котёл автоматически уменьшается,
чтобы не выдавливать кнопки за пределы видимой области.

Состав котла хранится в `localStorage`, поэтому переживает перезагрузку страницы
и не мешает другим подключённым устройствам.

## База данных

Ингредиенты, эффекты и пары антагонистов лежат в SQLite (`data/alchemy.db`,
путь меняется переменной `ALCHEMY_DB`). При первом запросе база создаётся
и наполняется из старых Python-справочников `database/ingridients.py`
и `database/test_bd.py`, так что ничего не потерялось.

```bash
.venv/bin/python -m database.seed          # создать, если базы нет
.venv/bin/python -m database.seed --force  # перезалить из Python-файлов
```

После сида источник правды — база. Правки в `database/ingridients.py`
и `database/test_bd.py` на работающее приложение больше не влияют
(кроме случаев, когда базу пересоздают через `--force`).

Схема — `database/schema.sql`, четыре таблицы:

| Таблица | Зачем |
| --- | --- |
| `effect` | справочник эффектов; ингредиент ссылается на эффект по `id`, поэтому опечатка в названии эффекта невозможна |
| `antagonist` | пара антагонистов хранится один раз в каноническом порядке, симметричность восстанавливает репозиторий |
| `ingredient` | название, омнисенция, редкость (`CHECK` допустимых значений) |
| `ingredient_effect` | состав ингредиента; `position` нужен, потому что дубли значимы: «урон» дважды — это два эффекта |

Соединение с базой берётся на каждый HTTP-запрос (`database/db.py`): `sqlite3`
не умеет безопасно шарить одно соединение между потоками, а Flask по умолчанию
многопоточный.

## Админка

`http://<ip>:8000/admin` — список ингредиентов, форма создания и редактирования,
удаление, справочник эффектов и пар антагонистов. Изменения сразу видны
на странице варки: она читает тот же каталог из базы.

Проверки живут на сервере (`database/repository.py`): пустое имя, дубль имени
без учёта регистра, неизвестный эффект, недопустимая редкость, нецелая
омнисенция. Поэтому через админку нельзя сохранить данные, которые потом
сломают расчёт.

По умолчанию админка открыта всем в локальной сети. Пароль включается так:

```bash
ALCHEMY_ADMIN_PASSWORD=секрет .venv/bin/python app.py
```

Логин — `admin` (меняется через `ALCHEMY_ADMIN_USER`). Это обычная HTTP Basic
авторизация: по локальной сети трафик не шифруется, для дома нормально.

Консольный `main.py` по-прежнему читает `database/ingridients.py` и
`database/test_bd.py` — он остаётся legacy-версией и с базой не связан.

### Если с телефона страница не открывается

Файрвол Fedora по умолчанию держит интерфейс в зоне `public`, где порт 8000
закрыт. Открыть **навсегда**:

```bash
sudo firewall-cmd --permanent --zone=public --add-port=8000/tcp
sudo firewall-cmd --reload
```

Проверить, что правило применилось:

```bash
firewall-cmd --list-all | grep -E 'interfaces|ports'
```

Вариант без `--permanent` работает только до перезагрузки или
`systemctl restart firewalld` — после этого телефон снова перестанет подключаться.

Если порт открыт, а страница всё равно не грузится:

1. Убедиться, что это не «гостевая» сеть и не отдельный VLAN (2.4 ГГц и 5 ГГц
   на некоторых роутерах — разные подсети).
2. Проверить в настройках роутера изоляцию клиентов (AP isolation /
   client isolation / «запретить обмен между устройствами»). В общежитиях и
   коворкингах её часто включают. Раздача с телефона — быстрый обход.
3. Посмотреть, доходят ли пакеты: на ноутбуке во время попытки подключения
   `sudo tcpdump -ni any port 8000`. Тишина — пакеты не доходят (роутер,
   изоляция). Пакеты есть, ответа нет — файрвол.

### Почему в логах каждые 30 секунд `GET /health 404`

Это не приложение. Сам OpenCode (`User-Agent: opencode/prod/...`) сканирует
`127.0.0.1:8000` в поисках локального сервера моделей и дёргает `/health` и
`/v1/models`. Безвредно, но засоряет логи. Запуск на другом порту убирает шум:

```bash
ALCHEMY_PORT=8080 .venv/bin/python app.py
```

Тогда и в файрволе открывать нужно 8080, а не 8000.

## Как считает сервер

- Эффекты всех ингредиентов складываются в общий список (дубли учитываются).
- Взаимно противоположные пары (таблица `antagonist` в базе, изначально —
  `database/test_bd.py`) гасятся по одной паре за раз.
- Итоговая омнисенция — сумма омнисенций ингредиентов, приведённая к диапазону
  из `database/omnisention_info.py` (`OMNISENTION_GRADUET`) по числу
  оставшихся эффектов. Недостача закрывается кристаллами ихора (+5 за штуку),
  излишек — кристаллами кенома (−5 за штуку).

## Структура

```
app.py                    Flask-приложение, публичный API и API админки
database/schema.sql       схема SQLite
database/db.py            подключение к базе (соединение на запрос)
database/seed.py          первичное наполнение из Python-справочников
database/repository.py    чтение каталога, CRUD и валидация
database/ingridients.py   исходные данные для сида (legacy)
database/test_bd.py       исходные пары антагонистов (legacy)
core/                     Ingridient, Mixed (логика смешивания), Potion
web/index.html            страница варки
web/admin.html            админка
web/static/               стили и клиентский JS (без сборки и CDN)
main.py                   консольная версия
```

## API

| Метод  | Путь                                  | Назначение                              |
| ------ | ------------------------------------- | --------------------------------------- |
| GET    | `/api/ingredients`                    | каталог ингредиентов                    |
| GET    | `/api/rules`                          | антагонисты, градация, лимит количества |
| POST   | `/api/brew`                           | расчёт зелья                            |
| GET    | `/api/admin/data`                     | ингредиенты + эффекты + пары для админки |
| POST   | `/api/admin/ingredients`              | создать ингредиент                      |
| PUT    | `/api/admin/ingredients/<id>`         | изменить ингредиент                     |
| DELETE | `/api/admin/ingredients/<id>`         | удалить ингредиент                      |
| POST   | `/api/admin/effects`                  | добавить эффект в справочник            |
| POST   | `/api/admin/antagonists`              | добавить пару антагонистов              |
| DELETE | `/api/admin/antagonists?effect=&antieffect=` | удалить пару                     |

```bash
curl -s http://127.0.0.1:8000/api/brew \
  -H 'Content-Type: application/json' \
  -d '{"ingredients":[{"name":"Черная роза","count":2},{"name":"небесный плач","count":1}]}'
```

Ответ (сокращённо):

```json
{
  "recept": ["Черная роза", "Черная роза", "небесный плач"],
  "properties": ["отравление", "снятие эффекта зелья", "отравление", "снятие эффекта зелья", "снятие эффекта"],
  "effects": [
    { "name": "отравление", "count": 2 },
    { "name": "снятие эффекта зелья", "count": 2 },
    { "name": "снятие эффекта", "count": 1 }
  ],
  "omnisention": 175,
  "raw_omnisention": 175,
  "crystals": [],
  "removed": [{ "effect": "плюс хит", "antieffect": "урон", "count": 2 }]
}
```

- `properties` — плоский список эффектов как есть (дубли важны: 7 эффектов и 5 эффектов
  попадают в разные диапазоны градации).
- `effects` — те же данные, сгруппированные для отображения.
- `removed` — какие пары антагонистов погасли.
- `crystals` — чего не хватало/было лишним и сколько кристаллов добавил сервер.

## Состояние и несколько пользователей

Котёл каждого посетителя хранится в его браузере (`localStorage`), сервер
ничего не запоминает между запросами. Поэтому несколько человек могут открыть
страницу одновременно и варить независимо друг от друга.
